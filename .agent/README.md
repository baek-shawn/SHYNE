# 에이전트 작업 인계 운영 규칙

이 디렉터리는 Codex나 Claude Code의 전체 대화 또는 로컬 세션을 저장하지 않는다. 회사, 집,
노트북처럼 서로 다른 개발 환경에서 Git을 통해 현재 작업 맥락을 전달하기 위한 짧고 검증 가능한
프로젝트 상태만 저장한다.

## 문서 역할

- `HANDOFF.md`: 현재 작업 상태를 나타내는 단일 문서다. 기록을 계속 누적하지 않고 항상 최신 상태로 덮어쓴다.
- `docs/HISTORY.md`: 완료된 실제 변경을 시간순으로 누적하는 과거 이력이다.
- `docs/ROADMAP.md`: 장기 제품 방향과 Step 1~13 구현 단계, 비교 실험 방법론이다 ("무엇을" 만들지).
- `docs/DEPLOYMENT_TODO.md`: 다른 PC(집/노트북)로 개발 환경을 이전하거나, vLLM/외부 API 연결
  설정을 옮길 때 남은 작업이다.
- 루트 `dev_step.md`: 지금 진행 중인 Step 하나를 "어떻게" 구현할지 상세히 적는 문서다.
  `HANDOFF.md`처럼 항상 현재 Step 하나만 담고, Step이 끝나면 삭제 후 다음 Step 문서로 교체한다.
  작성/삭제 절차는 `CLAUDE.md`의 "Step 개발 프로세스" 절을 따른다.

## 작업 시작 절차

1. `CLAUDE.md`의 공통 프로젝트 지침을 확인한다.
2. `HANDOFF.md`를 읽는다.
3. `git status`, 현재 브랜치와 최근 커밋을 확인한다.
4. 작업 인계 내용과 실제 코드가 일치하는지 확인한다.
5. 현재 요청과 관련된 `ROADMAP`, `DEPLOYMENT_TODO`, `HISTORY`만 선택해서 읽는다.
6. Step 구현을 요청받았다면 루트에 `dev_step.md`가 있는지 확인한다. 없으면 코드 작성 전에 먼저
   작성해서 사용자 승인을 받는다.

문서와 실제 코드가 다르면 코드와 Git 상태를 기준으로 판단하고, 작업이 끝날 때 `HANDOFF.md`를
수정한다.

## 작업 종료 또는 중단 절차

실제 코드, 설정, 파일 구조, 문서 구조 또는 프로젝트 설계가 변경됐다면 다음을 수행한다.

1. 관련 검증을 실행한다.
2. `docs/HISTORY.md` 끝에 완료된 변경과 검증 결과를 요약한다.
3. `HANDOFF.md`를 현재 상태로 덮어쓴다.
4. 사용자에게 변경과 검증 결과를 알린다.

작업을 완료하지 못하고 다른 PC나 다음 세션으로 넘길 때는 변경 이력에 완료된 사실만 기록하고,
진행 중인 문제와 다음 단계는 `HANDOFF.md`에 기록한다.

에이전트는 사용자의 명시적인 요청 없이 commit이나 push를 실행하지 않는다.

## `HANDOFF.md` 작성 기준

다음 항목만 간결하게 유지한다.

- 마지막 갱신 시각과 시간대
- 현재 목표와 상태
- 완료한 작업
- 남은 작업과 우선순위
- 확인된 문제 또는 차단 요인
- 관련 파일
- 마지막 검증 명령과 결과

전체 대화, 긴 코드 조각, 모든 실행 명령, 이미 끝난 과거 작업을 계속 쌓지 않는다. 현재 진행 중인
작업이 없다면 그 사실과 다음 권장 작업만 명시한다.

## `docs/HISTORY.md` 작성 기준

- 실제 코드, 설정, 파일 구조, 문서 구조 또는 프로젝트 설계가 변경된 경우에만 추가한다.
- 단순 질문과 답변, 상태 확인, 읽기 전용 조사, 변경 없는 진단과 검토는 기록하지 않는다.
- 계획만 세우고 실제 변경하지 않은 경우도 기록하지 않는다.
- 각 기록은 `===================================`로 시작한다.
- 다음 줄에 `시작 시간: YYYY-MM-DD HH:mm:ss KST` 형식으로 변경 작업의 시작 시각을 적는다.
- 작업 목적, 요약 계획, 실제 변경 사항과 검증 결과를 남긴다.
- 기존 기록은 사실관계 오류를 고치는 경우를 제외하고 수정하거나 재정렬하지 않는다.

## 기록하면 안 되는 정보

- API 키, 인증 토큰, 비밀번호와 `.env` 내용
- 사내 vLLM 서버 주소, 접속 정보 등 회사 내부 비밀
- 개인 계정 정보
- 특정 PC에서만 유효한 사용자명과 민감한 절대 경로
- Codex나 Claude Code의 원본 세션 파일과 전체 대화 로그

환경별 차이가 작업에 중요하면 비밀값이나 절대 경로 대신 필요한 프로그램 버전, 운영체제,
환경 변수 이름과 재현 절차만 기록한다.

## 나중에 추가할 수 있는 문서

다음 문서는 실제 문제가 반복될 때만 추가한다.

- `docs/DECISIONS.md`: 중요한 아키텍처 선택의 배경과 이유를 코드 및 변경 이력만으로 파악하기 어려울 때 추가한다.
- `.agent/EXPERIMENTS.md`: MyAgent와 OpenCode/Codex/Claude Code 비교 실험 중 의미 있는 실패
  사례가 여러 환경에서 반복될 때 추가한다.

새 문서를 만들면 루트 `README.md`의 문서 표와 `CLAUDE.md`의 읽기 규칙도 함께 갱신한다.
